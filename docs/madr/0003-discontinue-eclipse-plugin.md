# Discontinue the Eclipse Plugin (Language Server and Standalone Library only)

## Context and Problem Statement

Context Mapper has been provided as Eclipse plugin, as VS Code extension (based on our language server) and as standalone library. The Eclipse plugin requires a second build (Maven/Tycho with an Eclipse target platform, p2 update sites) besides the Gradle build of the standalone library and the language server. Keeping this stack up to date has become expensive: every Xtext update requires updating the Eclipse target platform (the current one, Eclipse 2026-03, needs Java 21 for the build), Orbit renamed bundles (for example `org.apache.commons.io`, which broke the installation of the 6.12.1 snapshot), and the Eclipse UI code (handlers, wizards, quick fixes) duplicates the functionality the language server offers to VS Code.

## Considered Options

* Keep the Eclipse plugin and the Maven/Tycho build
* Discontinue the Eclipse plugin; provide the language server (for the VS Code extension) and the standalone library only

## Decision Outcome

Chosen option: "Discontinue the Eclipse plugin", because the VS Code extension offers (almost) the same functionality via the language server, and a single Gradle build (as generated by the Xtext project wizard for language-server-only projects) is much easier to maintain.

Version 6.12.0 is the last version of the Eclipse plugin; its update site and marketplace entry stay available.

### Consequences

* Good, because there is only one build (Gradle) and no Eclipse target platform, Tycho, p2 update sites, OSGi manifests and Eclipse UI code to maintain anymore.
* Good, because Xtext updates only depend on the Xtext Maven artifacts.
* Bad, because Eclipse users do not get new versions anymore.
* Bad, because the following features were only available in Eclipse:
  * the XMI generator as IDE command (the generator itself is still part of the standalone library: `XMIGenerator`)
  * the "New CML File" wizard and the Freemarker template examples wizard (the templates moved to `samples/freemarker`)
  * Eclipse-specific editor features: quick outline, structure compare editor, preference pages to configure validation severities, the "Generators" and "Refactor" quick menus
